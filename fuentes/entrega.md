# Checklist ENTREGA · 10 cosas que le entregas a tu cliente antes del último pago

Abre el proyecto en Claude Code y pega cada prompt. Claude **revisa primero y te dice qué encontró**; tú decides qué hacer. **Nunca pegues en el chat llaves, tokens ni contraseñas:** para la lista de accesos, Claude solo anota dónde vive cada una, no su valor.

Antes de empezar, pega esto una vez:
```
Vas a ayudarme a preparar la entrega de este proyecto a mi cliente antes de cobrar el último pago. Para cada punto que te pida:
1) revisa el proyecto y dime qué ya está listo y qué falta;
2) explícame en una frase por qué le importa al cliente;
3) prepara el borrador o los pasos, pero NO cambies nada del proyecto hasta que yo diga «sí».
Si te falta un dato (dónde está publicado, qué servicios usa, quién paga cada uno), pregúntamelo.
```

## 1 · Dominio a su nombre
```
Dime qué dominio usa el proyecto y pregúntame a nombre de quién está y dónde se compró. Dame los pasos para transferirlo a una cuenta del cliente (o cambiar el titular) sin que la página se caiga, y cómo dejar la renovación automática con su tarjeta.
```

## 2 · Hosting y base de datos con él como dueño
```
Haz una lista de cada servicio donde corre el proyecto (hosting, base de datos, almacenamiento, correo, pagos) y de quién es cada cuenta. Para cada una, dame los pasos para que el cliente quede como dueño y yo como colaborador, sin perder datos ni tiempo de servicio.
```

## 3 · Repositorio transferido
```
Revisa el repositorio: que no tenga llaves ni archivos .env en el historial, que el README explique cómo instalar y publicar, y que la rama principal sea la que está en producción. Luego dame los pasos para transferirlo a la cuenta u organización del cliente y quedarme como colaborador.
```

## 4 · Lista de accesos y dónde viven
```
Haz una tabla con cada llave, token o contraseña que usa el proyecto: para qué sirve, en qué servicio se genera, dónde está guardada (variable de entorno, panel del hosting) y cómo se cambia. NO escribas ningún valor. Agrega cómo compartirlas con el cliente sin pegarlas en un chat (que él genere las suyas o un gestor de contraseñas).
```

## 5 · Manual de uso
```
Escribe un manual de uso para el cliente, sin tecnicismos y de máximo dos hojas: qué puede hacer en la app, cómo hacer las 5 tareas más comunes paso a paso, qué hacer si algo falla y a quién contactar. Usa lo que encuentres en el proyecto; lo que no sepas, déjalo marcado.
```

## 6 · Video de 5 minutos (te ahorra pleitos)
```
Escribe el guion de un video de 5 minutos para el equipo del cliente: qué mostrar en pantalla y qué decir en cada minuto, en el orden en que lo usarían en un día normal. Yo lo grabo con mi pantalla.
```

## 7 · Respaldo inicial
```
Dime qué datos guarda el proyecto y si hay respaldo automático. Dame los pasos para sacar un respaldo completo el día de la entrega, dónde guardarlo (en una cuenta del cliente) y cómo restaurarlo en un entorno de prueba para comprobar que sirve.
```

## 8 · Costos mensuales por escrito
```
Haz una tabla con cada servicio que cobra cada mes (hosting, base de datos, dominio, IA, correo, mensajes): plan actual, costo aproximado en un mes normal y en un mes fuerte, y qué pasa si se deja de pagar. Escríbela en lenguaje del cliente para anexarla a la entrega.
```

## 9 · Acuerdo de soporte con horas
```
Escribe un borrador corto de acuerdo de soporte: cuántas horas al mes incluye, qué cuenta como soporte y qué como cambio nuevo, en cuánto tiempo respondo, precio de la hora extra y cómo se pide. No es asesoría legal: lo revisamos el cliente y yo.
```

## 10 · Carta de entrega firmada (la que casi nadie pide)
```
Escribe una carta de entrega de una hoja: lista de lo que se entregó (con los links de cada cuenta y documento), lo que quedó fuera del alcance, la fecha y espacio para la firma de los dos. Que el cliente la firme el día que recibe todo y antes del último pago. No es asesoría legal.
```
Guárdala junto con el contrato.
